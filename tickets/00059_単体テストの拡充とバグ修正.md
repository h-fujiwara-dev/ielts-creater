## 実現すること

`ielts-creater-frontend`（[#00031](./00031_画面（S-01〜S-09）単体テストの導入.md)でVitest + React Testing Library基盤を新規導入しS-01〜S-09全画面・ロジック層を一括カバー）・`ielts-creater-backend`（各API実装チケット内でJUnitテストを継続的に追加）とも、機能実装のたびにテストは積み上がってきたが、**機能横断でテストの手薄な箇所を俯瞰した監査は一度も行われていない**。特に[#00056](./00056_ゲスト機能（共有デモアカウント方式）の実装.md)（ゲスト機能）で追加されたfrontend側コンポーネントはAC上テスト追加が明記されておらず抜け漏れの可能性がある。カバレッジ計測（機械的な洗い出し）と機能領域レビュー（新しめ・複雑な機能を優先した人力レビュー）を組み合わせて手薄な箇所を洗い出し、単体テストを拡充する。あわせてテスト作成中に見つかった不具合を修正する。

- frontend:
  - `npm test -- --coverage`等でカバレッジを計測し、数値の低いファイル・未テストのコンポーネント/`src/lib/`配下の関数を洗い出す
  - [#00056](./00056_ゲスト機能（共有デモアカウント方式）の実装.md)で追加されたコンポーネント（`GuestSignInButton`、`src/auth.ts`のCredentialsプロバイダー(`guest`)分岐、ゲスト利用中バッジ表示等）を優先的に確認する
  - [#00054](./00054_Listening機能の不具合修正.md)で修正された`audio-player.tsx`等の主要分岐（再生/一時停止/エラー時）のテスト網羅度を確認する
  - 洗い出した手薄な箇所に単体テストを追加する
- backend:
  - `./gradlew test jacocoTestReport`（Jacoco未導入の場合は導入を検討する）等でカバレッジを計測し、サービス層・コントローラ層・採点ロジックの中で手薄な箇所を洗い出す
  - [#00056](./00056_ゲスト機能（共有デモアカウント方式）の実装.md)で追加された`GuestQuotaInterceptor`（同一/異なるIPからの同時リクエスト時の原子性）、`GuestDataCleanupService`（24時間境界値・S3/ローカルファイル削除呼び出し）等、新しめの機能のエッジケース網羅度を優先確認する
  - 洗い出した手薄な箇所に単体テストを追加する
- テスト作成中に見つかった軽微な不具合はこのチケット内で修正する。大きな仕様変更を要する不具合が見つかった場合は新規チケットとして切り出し、本チケットの作業ログにリンクを記載する
- 対象外: Playwright E2EテストのCI組み込み（[#00047](./00047_PlaywrightによるE2Eテストの導入.md)で意図的に対象外とされた既知の積み残し、別チケットで対応）、`ielts-creater-infra`（Terraformのみでユニットテストの概念が薄いため対象外）、カバレッジ数値目標の設定（今回は[#00031](./00031_画面（S-01〜S-09）単体テストの導入.md)と同様の粒度感で「主要機能領域を一通りカバーしたら完了」とし、数値目標は設けない）
