## 実現すること

実装規約.md（#00015）に基づき、Spring Bootバックエンドプロジェクトの雛形（ビルド構成・パッケージ構成・DBマイグレーション・CI・Phase1向け認証スタブ）を構築し、以降の機能別チケット（受験・採点APIなど）が着手できる状態にする。個々のエンドポイントのビジネスロジック実装は対象外。次チケットでは受験・回答・採点API（attempt系）に着手する想定。

## 受け入れ条件

- [ ] Gradle（Groovy DSL）+ Java 21 + Spring Boot 3系のプロジェクトを作成し、実装規約.md 1章の主要依存関係（web / data-jpa / oauth2-resource-server / validation / flyway-database-postgresql / postgresql / logstash-logback-encoder / actuator、テストは spring-boot-starter-test / testcontainers-postgresql / testcontainers-junit-jupiter）を追加する
- [ ] Spotless（Google Java Format）と Lombok（io.freefair.lombok）を導入し、`./gradlew spotlessCheck` が通る状態にする
- [ ] 実装規約.md 2章のパッケージ構成（`common` / `user` / `questionset` / `attempt` / `dashboard`）の空パッケージを作成する（ビジネスロジッククラスは含めない）
- [ ] `common/exception` に `GlobalExceptionHandler`（`@RestControllerAdvice`）と、API一覧.md 2章のエラーレスポンス形式（`error`/`message`/`timestamp`）・例外種別→HTTPステータス対応の枠組みを実装する（個別の業務例外は各機能チケットで追加）
- [ ] Flywayマイグレーション `V1__init.sql` を ER図・テーブル定義.md 3章の11テーブル定義（app_user / question_set / passage / listening_script / audio_segment / question_group / question / answer_option / acceptable_answer / attempt / attempt_answer、記載インデックス含む）に基づき作成する
- [ ] `application.yml` / `application-local.yml` を作成する（`application-local`は`docker-compose.yml`のPostgres接続情報を使用し、`spring.jpa.hibernate.ddl-auto=validate`固定）
- [ ] Phase1向け`SecurityConfig`を作成する（no-authプロファイル等でCognito検証をスキップし、固定の開発用ユーザーを解決できるようにする）。実際のCognito JWT検証は実装規約R-2としてPhase2着手時の別チケットで対応し、本チケットでは実装しない
- [ ] 固定の開発用`app_user`レコードをローカル環境で解決できるようにする（以降のチケットが受験者ユーザーIDとして利用できる形を用意する）
- [ ] `logback-spring.xml`で`logstash-logback-encoder`によるJSON構造化ログを設定し、`traceId`採番用のServletフィルタを実装する（API一覧.md 4章の必須フィールドの下地。`userId`のMDC格納はCognito認証実装時に追加）
- [ ] GitHub Actions CI に `./gradlew spotlessCheck test` を必須チェックとして追加する（実装規約.md 1.3 / R-1 の解消）
- [ ] `./gradlew bootRun` でローカル起動でき、`GET /actuator/health` が200を返すことを確認する
- [ ] READMEにローカル起動手順（`docker-compose up -d` → `./gradlew bootRun` 等）を追記する
