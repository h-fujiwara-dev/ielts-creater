# #00026 運用ルール改善（チケットステータス簡素化・PR承認必須化・ブランチ自動更新）

- 対象リポジトリ: root / frontend / backend / infra
- ステータス: 未対応
- type: chore
- 関連ドキュメント: [tickets/README.md](./README.md) / [tickets/_template.md](./_template.md) / [CLAUDE.md](../CLAUDE.md) / [.github/workflows/auto-pr.yml](../.github/workflows/auto-pr.yml)

## 実現すること

以下3点の運用改善をまとめて実施する。

- チケットステータスを「未着手/進行中/完了」の3段階から「未対応/完了」の2段階に簡素化する
- root/frontend/backend/infra 4リポジトリすべてで、PRのマージにユーザー自身のapprove（レビュー1件）を必須化する（`required_approving_review_count: 1`）。developからmainへのリリースPRはユーザー自身のアカウントで作成すると自分では承認できない（GitHub仕様上の自己承認不可制約）ため、`release-pr.yml`（`workflow_dispatch`）を新設し、`github-actions[bot]`がリリースPRを作成するようにする
- 承認必須化によりPRが開いている時間が伸び、`This branch is out-of-date with the base branch` の発生頻度が上がる見込みのため、`auto-update-branch.yml`を新設し、develop/mainへのpush時にオープン中PRのブランチを自動最新化する

- [ ] root/frontend/backend/infra 4リポジトリのbranch protection（main・develop）で`required_approving_review_count`が1に設定されている
