# #00040 ログイン後のディープリンク保持

- 対象リポジトリ: frontend
- ステータス: 完了
- type: fix
- 関連ドキュメント: [#00034 Cognito認証の本実装](./00034_Cognito認証の本実装.md)

## 実現すること

`src/middleware.ts`は未認証ユーザーを`/login`へリダイレクトする際に`callbackUrl`クエリを付与しておらず、`CognitoSignInButton`側も`callbackUrl: "/dashboard"`を固定で渡している。そのため、`/history`や`/attempts/[attemptId]/result`等の保護ページへの直リンク（ブックマーク等）を未ログイン状態で開いた場合、ログイン完了後は常に`/dashboard`に飛ばされ、元々開こうとしていたページに到達できない。

修正方針:

1. `middleware.ts`のリダイレクトで、元のリクエストURL（pathname+search）を`callbackUrl`クエリとして`/login`に付与する
2. `/login`ページ・`CognitoSignInButton`が`callbackUrl`クエリを受け取り、`signIn("cognito", { callbackUrl })`に渡すようにする（クエリが無い場合のみ`/dashboard`にフォールバック）
3. `callbackUrl`はオープンリダイレクト対策として自オリジン配下のパスのみ許容するようにする

- [ ] dev serverで実際にディープリンク→ログイン→元ページ復帰の流れを確認する（ディープリンク→`/login?callbackUrl=...`遷移まではブラウザで実確認済み。ログイン→元ページ復帰は実AWS環境にCognito User Poolが未払い出しのため未確認。#00038/#00039と同じ既知の残課題）
