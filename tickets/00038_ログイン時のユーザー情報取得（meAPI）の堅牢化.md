# #00038 ログイン時のユーザー情報取得（me API）の堅牢化

- 対象リポジトリ: frontend
- ステータス: 完了
- type: fix
- 関連ドキュメント: [#00034 Cognito認証の本実装](./00034_Cognito認証の本実装.md)

## 実現すること

`src/auth.ts`のNextAuth `jwt`コールバックは、Cognitoサインイン直後の`if (account)`ブロック内でのみ`fetchMe()`（`GET /api/v1/me`呼び出し）を実行し、成功時に`token.appUserId`をセットする。この一発呼び出しにはリトライ・タイムアウト・レスポンス検証がなく、バックエンドが一時的に応答しない/遅い/レスポンス形状が変わった場合、`appUserId`が二度とセットされないままセッションが確立してしまう。結果、`(protected)/layout.tsx`の`if (!session?.user?.id) redirect("/login")`により、再ログインしてもバックエンドが不調な限り永久に`/login`へ跳ね返され続ける（ユーザーからは原因不明のログイン不能に見える）。

また、`middleware.ts`は`!req.auth`のみで認可判定し、`(protected)/layout.tsx`は`!session?.user?.id`で判定するという二重基準になっており、上記の中途半端なセッション（`req.auth`はtrueだが`user.id`がない）でmiddlewareは素通りさせてしまう（実質的な無駄なホップ）。email/displayNameもfetchMe()の結果のみに依存しており、同じOAuth交換で既に取得済みのCognito OIDCクレーム（email等）をフォールバックとして使っていない。

`docs/画面設計書/S-02_ログインサインアップ画面.md`は、チケット#00034での実装置き換え（dev-user/mock-session関連コードの削除）後も「Phase1のno-authモードでは固定devユーザーでログイン不要のまま画面を確認できる」という趣旨の記述が残っており、実装と乖離している。本チケットで実態に合わせて修正する。

修正方針:

1. `fetchMe()`にタイムアウト（`AbortSignal.timeout()`等）を設定する
2. `fetchMe()`のレスポンスを型キャストのみでなく実行時バリデーションする（zod等、既存`src/lib/question-sets/schemas.ts`のパターンを踏襲）
3. 失敗時にサーバーログを出す（原因が握りつぶされないようにする）。ネットワークエラー/非2xx/形状不一致を区別できるようにする
4. `token.appUserId`が未設定な状態でセッションが確立した場合、後続リクエスト時に再度`fetchMe()`をリトライする仕組みを追加する（毎リクエストではなく妥当な間隔で）
5. email/displayNameが取得できない場合、Cognito OIDCプロファイルクレームの値をフォールバックとして使う
6. `middleware.ts`と`(protected)/layout.tsx`の認可判定基準を1つの共有関数に統一する
7. `docs/画面設計書/S-02_ログインサインアップ画面.md`のPhase1（no-auth）に関する記述を、dev-user/mock-session削除後の実態に合わせて修正する

## 受け入れ条件

- [x] `fetchMe()`にタイムアウトを設定し、無期限にブロックしない
- [x] `fetchMe()`のレスポンスを実行時検証し、形状不一致時はエラーとして扱い、ログに残す
- [x] `fetchMe()`の失敗理由（ネットワークエラー/非2xx/形状不一致）がサーバーログから判別できる
- [x] `token.appUserId`が未設定のままセッションが確立しても、後続リクエストで復旧できる（無限ログインループにならない）
- [x] email/displayNameが`fetchMe()`から取得できない場合、OIDCクレームをフォールバックとして使う
- [x] `middleware.ts`と`(protected)/layout.tsx`の認可判定基準が1箇所に統一されている
- [x] S-02設計書のPhase1（no-auth）記述が実装と一致するよう修正されている
- [x] `npx tsc --noEmit` / `npm run lint` / `npm run build` / `npm run test`が通る
- [ ] バックエンドを一時的に落とした状態でログインを試み、原因不明のループにならず適切に扱われることを手動確認する（実AWS環境にCognito User Poolが未払い出しのため、本チケットでは検証不可。#00034時点からの既知の残課題であり、Cognito払い出し後にあらためて手動確認する）
