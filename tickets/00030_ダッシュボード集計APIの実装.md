## 実現すること

API一覧.md（11エンドポイント）のうち#00028（受験・回答・採点API）・#00029（問題生成API）が対象外とした残りのエンドポイントは`GET /api/v1/me`と`GET /api/v1/dashboard/summary`の2本。`GET /api/v1/me`はCognitoログイン後の自動プロビジョニング確認用（ロードマップ上Phase2のCognito連携スコープ）のため対象外とし、本チケットでは#00028で構築したAttempt/AttemptAnswer等のデータを用いてダッシュボード集計API`GET /api/v1/dashboard/summary`を実装する。新規JPAエンティティは不要（Attempt/AttemptAnswer/QuestionSet/QuestionGroup/Questionは#00028で作成済み）。

## 受け入れ条件

- [ ] `dashboard`パッケージに`DashboardController`/`DashboardSummaryService`を実装する
- [ ] `GET /api/v1/dashboard/summary`を実装する（`period`=`7D`/`30D`/`90D`/`ALL`〈デフォルト`ALL`〉、`section`=`READING`/`LISTENING`〈任意〉のクエリパラメータ。`status=SUBMITTED`のAttemptのみ対象、`AttemptRepository.findHistory`と同様に`QuestionSet`をjoinして絞り込む）
- [ ] `totalAttempts`・`averageAccuracyBySection`・`scoreTrend`（日付単位の正答率推移）・`accuracyByFormat`（`attempt_answer`と`question`→`question_group.format_type`をjoinして集計）をDBクエリで集計する
- [ ] `period`による相対期間フィルタ（`submitted_at`基準）をクエリで実装する
- [ ] `section`指定時は`averageAccuracyBySection`/`accuracyByFormat`が指定セクションのみの値になるようにする（API設計書の仕様通り）
- [ ] 不正な`period`/`section`値は400（`ValidationException`。#00027で実装済みの`GlobalExceptionHandler`を利用）を返す
- [ ] 認証はPhase1方針を踏襲し、`CurrentUserProvider`（固定devユーザー）を使用する
- [ ] Unit Test（Mockito）で集計ロジック・パラメータバリデーションを検証する
- [ ] 結合テスト（Testcontainers, `@Tag("integration")`）で、複数Attempt/AttemptAnswerを投入した上で4出題形式・複数セクションにまたがる集計結果、および`period`/`section`フィルタの挙動を検証する
- [ ] `./gradlew spotlessCheck test integrationTest` がグリーンであることを確認する
