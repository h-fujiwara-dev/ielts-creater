# #00039 ログインエラー表示の到達性修正とサインインボタンのフリーズ修正

- 対象リポジトリ: frontend
- ステータス: 未対応
- type: fix
- 関連ドキュメント: [#00034 Cognito認証の本実装](./00034_Cognito認証の本実装.md)

## 実現すること

チケット#00034で`src/app/(auth)/login/page.tsx`にCognito認証エラー用の`AuthAlert`が追加されたが、`src/auth.ts`のNextAuth設定に`pages: { signIn: "/login" }`が指定されていないため、実際のOAuthエラー（ユーザーによる同意拒否・state/PKCE不一致・AccessDenied等）発生時、NextAuthは自前の`/api/auth/signin?error=...`にリダイレクトしてしまい、追加した`AuthAlert`には到達しない。既存テストは`AuthAlert`コンポーネント単体の描画のみを検証しており、この実リダイレクト経路の欠落を検出できていない。

また、`src/components/auth/cognito-sign-in-button.tsx`の`signIn("cognito", ...)`呼び出しに`.catch()`がなく、リダイレクト前に通信エラーが起きるとボタンの`isPending`状態がリセットされないまま固まり、ページ再読み込みしないと復旧できない。

修正方針:

1. `src/auth.ts`に`pages: { signIn: "/login" }`（必要なら`error`も）を設定し、エラー時に`/login?error=...`へリダイレクトされるようにする
2. `cognito-sign-in-button.tsx`の`signIn()`呼び出しに`.catch()`を追加し、失敗時に`isPending`をリセットしてエラー表示する

## 受け入れ条件

- [ ] NextAuthのエラーリダイレクト先が`/login`になるよう設定されている
- [ ] Cognito側で同意拒否した場合に`/login`の`AuthAlert`が実際に表示されることを手動確認する
- [ ] `signIn()`が失敗した場合、ボタンが再度クリック可能な状態に戻り、エラーが表示される
- [ ] 上記2点を検証するテストを追加する
- [ ] `npx tsc --noEmit` / `npm run lint` / `npm run build` / `npm run test`が通る
