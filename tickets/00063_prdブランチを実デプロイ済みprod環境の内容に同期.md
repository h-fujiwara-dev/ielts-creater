## 実現すること

[#00062](./00062_TOP画面ボタンでCognitoサインイン-サインアップ画面を出し分け.md)（TOP画面のCognitoサインイン/サインアップ出し分け）でinfra側prod環境に`terraform plan`を実行したところ、`prd`ブランチのTerraformコードが実際にAWSへデプロイ済みの内容より古いままであることが判明した。過去のいくつかの変更（ゲスト機能の本番反映#00058等）が、本来`prd`ブランチ向けに作成すべきPRを`develop`ブランチへ作成してしまっており、`prd`ブランチには一度もマージされていなかったことが原因と見られる。

この状態で`prd`ブランチのコードを使って`terraform apply`（`-target`指定なしの通常のapply）を実行すると、Terraformは「設定ファイルに存在しないリソース」とみなして以下を**削除**しようとしてしまう。

- `aws_cognito_user.guest`（本番ゲストアカウント本体）
- `aws_cognito_user_pool_client.guest`（ゲスト用App Client）
- `random_password.guest_user`

`terraform plan`（`-target`指定なしのフルプラン）で実際のAWS状態と突き合わせ、以下を`prd`ブランチのコードに反映する（実インフラへの変更は行わず、コードを実態に合わせるのみ）。

- ゲスト機能（#00056/#00058）: `terraform/modules/cognito`のguestプールクライアント・共有デモアカウント・`envs/prod/main.tf`のSecrets Manager連携・ECS環境変数一式
- API Gatewayでのクライアント実IP注入（ゲストのIPアドレス単位クォータに必要）
- ECSヘルスチェックの`startPeriod`延長 60秒→180秒（Spring Boot起動時間対策）
- GitHub Actions OIDC信頼ポリシーのsubクレームワイルドカード対応

## 受け入れ条件

- [ ] `prd`ブランチのコードに、実際にAWSへデプロイ済みのゲスト機能・API Gateway・ECS・OIDC関連の変更が反映されている
- [ ] 反映後の`terraform plan`（`-target`指定なしのフルプラン、prod環境）で、上記リソースの差分がゼロであることを確認する
- [ ] 実インフラへの変更は行わない（コードを実態に合わせるのみ）

## 既知の残課題（本チケットのスコープ外）

上記フルプラン実行中に、`terraform/modules/network`のNATインスタンスがAMI自動更新（`most_recent`想定）により置き換え対象と判定される、本チケットとは無関係な既存ドリフトを発見した（dev環境でも同様の事象を確認済み）。NATインスタンス置き換えは通信への短時間の影響が想定されるため、本チケットでは対応せず別チケットとして切り出す想定。
