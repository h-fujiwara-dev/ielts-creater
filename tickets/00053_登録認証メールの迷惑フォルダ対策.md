# #00053 登録認証メールの迷惑フォルダ対策（SES独自ドメイン送信の導入）

- 対象リポジトリ: infra
- ステータス: 未対応
- type: feat
- 関連ドキュメント: [#00034 Cognito認証の本実装](./00034_Cognito認証の本実装.md)

## 実現すること

dev環境での手動確認の結果、新規登録時の認証コードメールが迷惑メールフォルダに振り分けられることが分かった。`ielts-creater-infra/terraform/modules/cognito/main.tf`には`email_configuration`ブロックが存在せず、Cognitoのデフォルトメール送信（`no-reply@verificationemail.com`、送信ドメインの評判・到達率が低いことで知られる）を使用しているのが原因と考えられる。

対応方針:

1. SESで送信用ドメインを検証する（DKIM/SPFレコードの設定を含む）。現状infraにRoute53/SESを扱うモジュールが存在しないため、実装着手時にドメイン管理方法（既存ドメインの有無、DNS委任状況）を確認した上で必要なモジュールを追加する
2. Cognito User Poolの`email_configuration`を`email_sending_account = "DEVELOPER"`＋`source_arn`でSES経由に切り替える

## 受け入れ条件

- [ ] SESで送信ドメインの検証（DKIM/SPF）が完了している
- [ ] Cognitoからの確認メールが検証済みドメインのFromアドレスで送信される
- [ ] 実際に新規登録を行い、確認メールが迷惑フォルダに入らないことを手動確認する
