# チケット管理

プロジェクト全体（root / frontend / backend / infra の4リポジトリ）のチケットをこのリポジトリで一元管理する。

## 運用ルール

1. 新規チケットは [`_template.md`](./_template.md) をコピーし、`XXXXX_タイトル.md`（5桁ゼロ埋めの連番）として作成する。番号はこのリポジトリ全体を通して一意（既存の最大番号の次を使う）
2. チケットファイルは`docs/ticket-XXXXX`ブランチでdevelopへPRを出し、マージされてから実装ブランチを作成する（チケット定義と実装を同一の未マージブランチにまたがらせない）
3. ステータスは「未対応」「完了」の2段階。作成時は「未対応」のまま、完了時にのみ「完了」へ更新する（着手時のステータス変更は不要）。進捗は作業ログに日付を追記して記録する（更新は都度rootリポジトリのPRで反映する）
4. 1チケットは機能単位。複数リポジトリにまたがってよい（対象リポジトリに列挙する）
5. 作業対象の各リポジトリのコミットメッセージは `[#チケット番号] type: 概要` でチケットに紐づける（[各リポジトリのCLAUDE.mdのコミットメッセージ規則](../CLAUDE.md#コミットメッセージ規則)を参照）
6. チケット完了後もファイルは削除せず、このリポジトリの`tickets/`配下に残す（作業履歴として保持）
7. このREADMEにチケット一覧・番号は記載しない。個々のチケットは`tickets/`配下のファイルを直接参照する（`ls tickets/`で確認可能）。並行して複数チケットのブランチが作成されるため、一覧を都度更新する運用はコンフリクトの原因になりやすいため廃止した
