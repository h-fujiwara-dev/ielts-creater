## 実現すること

対象は、#00019〜#00023でfrontend実装したダッシュボード（S-07）・問題生成（S-03）・回答（S-04）・結果（S-05）・履歴一覧（S-06）の5画面は、いずれも`src/lib/{dashboard,attempts,question-sets}/mock-data.ts`のmock関数からデータを取得しており、実API接続は各チケットで明示的にスコープ外とされていた。backend側は#00027〜#00030でAPI一覧.md記載の11エンドポイントのうち`GET /api/v1/me`（Cognito連携が前提のためPhase2スコープ）を除く10本が実装済み・developにマージ済み。本チケットでは、上記5画面のmock関数を実HTTP呼び出しに置き換え、ローカルで起動したbackend（`SPRING_PROFILES_ACTIVE=local`、no-authモード、固定devユーザー）から実データを取得して画面表示できるようにする。

backendは無改修とする。backendにCORS設定がなくブラウザから`localhost:8080`を直接叩くとブロックされるため、frontend側にAPIプロキシ（Next.jsの`rewrites()`等）を新設し、同一オリジン経由でbackendへ転送する。認証は#00027の方針を踏襲し、Authorizationヘッダなし（no-authモード）を前提とする。Cognito連携・ログイン/サインアップ画面の実認証化・`GET /api/v1/me`によるユーザー情報取得は対象外（Phase2以降）。

## 受け入れ条件

- [x] Next.jsにbackend APIへのプロキシを追加する（`next.config.ts`の`rewrites()`。転送先は環境変数`BACKEND_API_ORIGIN`〈デフォルト`http://localhost:8080`〉から解決し、`/api/v1/:path*`をbackendへ転送する。`.env.example`に追記）
- [x] ダッシュボード画面（S-07）: `mockGetDashboardSummary`を`GET /api/v1/dashboard/summary`（`period`/`section`クエリ）への実呼び出しに置き換える
- [x] 問題生成画面（S-03）: `mockCreateQuestionSet`/`mockGetQuestionSet`を`POST /api/v1/question-sets`・`GET /api/v1/question-sets/{id}`（ポーリング）への実呼び出しに置き換える
- [x] 回答画面（S-04）: `mockGetQuestionSet`/`mockGetAudioSegments`/`mockStartAttempt`/`mockGetSavedAnswers`/`mockPatchAnswers`/`mockSubmitAttempt`を対応する実エンドポイントへの呼び出しに置き換える（Listening音声は`GET /api/v1/question-sets/{id}/audio-segments/{audioSegmentId}/file`から取得）
- [x] 結果画面（S-05）: `mockGetAttemptResult`を`GET /api/v1/attempts/{id}`への実呼び出しに置き換える。実レスポンスには設問文・submittedAt・durationが含まれないため、設問文は同時に取得する`GET /api/v1/question-sets/{id}`からquestionIdでマッピングし、submittedAt/durationは回答画面での開始・提出タイミングをクライアント側（`sessionStorage`等）で保持して結果画面に引き継ぐ方式に変更する
- [x] 履歴一覧画面（S-06）: `mockGetAttempts`を`GET /api/v1/attempts`（`section`/`page`/`size`クエリ、ページング）への実呼び出しに置き換える
- [x] backendのエラーレスポンス形式（`{error, message, timestamp}`）およびネットワークエラーを各画面でハンドリングする（既存のエラー表示UIがある画面はそれを利用し、ない画面は最低限のエラー表示を追加する）
- [x] mock専用の`simulateDelay`ラッパー・`src/lib/attempts/storage.ts`のmock結果永続化ロジックのうち実API移行後不要になった処理を整理する
- [x] `src/lib/auth/mock-user.ts`（`GET /api/v1/me`相当）・ログイン/サインアップ画面（`dev-user.ts`）は対象外とし、現状のモック実装のまま維持する
- [x] 上記画面変更に伴い、既存のVitestテスト（`dashboard-screen.test.tsx`/`history-screen.test.tsx`ほか#00031で追加した該当画面のテスト）を実API呼び出し前提に更新し、`fetch`をモックして全てgreenにする
- [x] backendをローカル起動（`docker compose up -d` → `SPRING_PROFILES_ACTIVE=local ./gradlew bootRun`、developブランチ）した状態で、5画面（S-03〜S-07）を実際にブラウザ操作し、問題生成→回答→採点結果→履歴一覧→ダッシュボード集計という一連のフローがmockではなく実データで動作することを確認する
- [x] `npm run lint` / `npm run build` / `npm run test`がgreenであることを確認する
