## 実現すること

TOP画面（S-01）は唯一の未ログイン公開画面であり、`業務要件定義書` §2.2で明記されている通り、サービス利用者向けの入口であると同時に**採用担当者・エンジニアが実装力を評価する画面**という役割も担う。

[#00066](./00066_TOPページビジュアル演出のモダン化.md)（WebGLメッシュグラデーションHero・Bentoグリッド+3Dチルト・技術スタックマーキー・マグネットボタン導入、「追加npm依存ゼロ・自前実装」方針）と[#00068](./00068_TOPページHero演出の視認性改善.md)（Hero視認性のコントラスト修正）で一度モダン化を実施済みだが、ユーザー（開発者本人）によるレビューの結果、以下3点の複合により依然として「古い・ダサい」印象が残ると判断した。

- **没個性・テンプレ感**: メッシュグラデーション+Bentoグリッド+ロゴマーキーの組み合わせは、今や「AIが自動生成したSaaSサイト」の定番構成になっており、差別化になっていない
- **実装・動きの質が甘い**: 演出のアイデア自体は悪くないが、モーションの滑らかさ・仕上げの精度が甘く安っぽく見える
- **配色・タイポグラフィが古い**: 動きとは独立して、色味・フォントそのものの印象が古い（Plus Jakarta Sans + Noto Sans JPは「モダンSaaS」の極めて量産的なデフォルト組み合わせ）

本チケットでは、[#00066](./00066_TOPページビジュアル演出のモダン化.md)までの「追加npm依存ゼロ・自前実装」方針を撤廃し、three.js/GSAP等の実践的なライブラリを導入した**本格的な3D/インタラクティブ表現**へ全面刷新することで、実務で使う技術選定・活用力そのものをアピールする。対象範囲はHeader〜Footerの全セクション。

対象リポジトリを`root`（本チケット定義）と`frontend`（実装）の両方とするが、[#00066](./00066_TOPページビジュアル演出のモダン化.md)と同様、**本チケットのマージ後に、developを起点とした別の実装ブランチで着手する**（チケット定義と実装を同一の未マージブランチにまたがらせない運用ルールに従う）。

実装内容は以下の通り。

### 1. Heroの3Dセンターピース「Band Staircase」

IELTSのスコアは「バンドスコア」（1〜9）と呼ばれる。抽象的なブロブやパーティクルではなく、バンドスコアという製品の核となる概念そのものを3D幾何形状にする。React Three Fiberで、1〜9のガラス質スラブが左下から右上へ階段状に積み上がるシーンを`src/components/three/`配下に新規実装する。

- バンド1〜8は`meshPhysicalMaterial`（navy寄りガラス、軽量）、バンド9のみdrei `MeshTransmissionMaterial`（ブランドオレンジ、高品質ガラスシェーダー）+ 専用`pointLight`で発光させ「到達目標」を視覚的に一点集中させる
- `Environment`はHDR画像を使わず`Lightformer`で手続き的に生成（バイナリアセット不要）。`@react-three/postprocessing`の`Bloom`をバンド9のみに適用
- 数字ラベルはdrei `Text`（SDF）で表示し、既存の`Geist Mono`（layout.tsx既存導入分）を再利用してフォント追加ロードなしとする
- カーソル追従パララックス（±0.12rad程度にクランプ、`window.matchMedia("(pointer: coarse)")`で無効化、既存`use-magnetic.ts`と同じパターン踏襲）とGSAP `ScrollTrigger`によるスクロール連動ビルドアップ（Hero到達時に一度だけ、9枚のスラブがstaggerしながら積み上がる）を実装する
- 既存の`GradientMesh`/`DotField`（`src/components/reactbits/`）およびHero右カラムのUnsplashストック写真は廃止し、3Dシーンを唯一のビジュアルフォーカスとする

### 2. タイポグラフィ刷新

ルート`layout.tsx`のフォントを`Plus Jakarta Sans + Noto Sans JP`から**`Geist`（欧文）+ `Zen Kaku Gothic New`（和文）**に変更する（`next/font/google`）。既存`Geist Mono`はバンドスコア数字・ステップ番号等の「技術的な仕様書」らしいテクスチャとして全面活用する。この変更はルートlayoutでの定義のためS-02〜S-07（認証・ダッシュボード等）にも全面適用され、サイト全体のタイポグラフィ一貫性として扱う。

### 3. 配色の進化（新規トークン追加なし）

既存ブランドトークン（`brand-navy`/`brand-navy-light`/`brand-orange`/`brand-orange-light`/`brand-blue`/`brand-lavender`/`brand-cream`）は変更しない（ダッシュボード等の認証後画面でも使用されているため）。

- Heroを`bg-brand-navy`の本格的なダーク背景に変更（`SiteFooter`が既に採用している既存パターンの延長）。コピーは白/creamに反転
- ダークHero → ライトボディ（既存トークンのまま） → ダークFooter（既存のまま）というブックエンド構成で最初の印象を刷新
- FeatureGridの全面`bg-brand-lavender`塗りを`bg-brand-cream`+カード単位アクセントに変更し、カードは`ring-1 ring-brand-navy/10`のヘアラインボーダーで輪郭を出す

### 4. 新規npm依存の追加

`three` / `@react-three/fiber` / `@react-three/drei` / `@react-three/postprocessing` + `postprocessing` / `gsap`。TOPルート専用チャンクへの追加は概算250〜300KB gzip程度。`next/dynamic(..., { ssr: false })` + Next.jsのルート単位コード分割で他ルートへの影響を遮断する。GSAPは2025年4月のWebflowによる無償化以降、商用利用含め無料（実装時に`gsap.com/pricing`で再確認する）。

### 5. 全セクション刷新

SiteHeader（Hero表示中は透過ダーク配色、スクロール後はライト配色に切替）、TrustBand/Story/TwoColCta/CtaBand（タイポグラフィ・カード意匠刷新）、FeatureGrid（GSAP `ScrollTrigger.batch()`による同期スタガー、`prefers-reduced-motion`時は既存`RevealOnScroll`版にフォールバック）、Insights（数字ウォーターマークでHeroのバンド数字と視覚的に呼応）、TechMarquee（Three.js/GSAPをクレジットに追加）、SiteFooter（バンド階段を想起させる9本バーの小装飾）。

### 6. パフォーマンス・アクセシビリティ対策

- `HeroScene`は`next/dynamic(..., { ssr: false })`でクライアント専用ロード。`usePrefersReducedMotion()`（既存）+ 新規`useWebglSupported()`で、フォールバック時は3DシーンのJSチャンク自体をfetchしない
- フォールバックは静的SVGの9本バー（canvas/rAF/GSAP不使用、既存`GradientMesh`等と同じ「軽減時は完全静止」の二値方針を踏襲）
- `<Canvas frameloop="demand" dpr={[1,2]}>`、Heroが画面内かつタブがフォアグラウンドの時のみ`invalidate()`をポンプ（既存`GradientMesh`のIntersectionObserverパターン踏襲）。drei `PerformanceMonitor`で低スペックGPU時にDPRを自動的に下げる
- 全ての`ScrollTrigger`/タイムラインは`useEffect`クリーンアップまたは`gsap.context()`で確実に`kill()`
- HeroのH1・本文はサーバーレンダリングで即座にペイントし、3D Canvas自体が絶対にLCP要素にならないようにする

### 7. クリーンアップ

`src/components/reactbits/gradient-mesh.tsx`（+`.css`/`.test.tsx`）、`dot-field.tsx`（+`.css`）を削除（Heroのみが利用しており、新3D表現と共存させる理由がないデッドコードになるため）。`spotlight-card.tsx`/`blur-text.tsx`は引き続き利用するため維持。`docs/画面設計書/S-01_Top画面.md`（frontendリポジトリ内）のカラー/タイポグラフィ表とビジュアル説明を更新し、参照スクリーンショットを差し替える。
