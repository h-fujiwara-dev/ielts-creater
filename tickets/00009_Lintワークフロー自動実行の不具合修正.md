# #00009 Lintワークフロー自動実行の不具合修正（action_required解消）

- 対象リポジトリ: root / frontend / backend / infra
- ステータス: 進行中
- type: ci
- 関連ドキュメント: [.github/workflows/lint.yml](../.github/workflows/lint.yml) / [.github/workflows/auto-pr.yml](../.github/workflows/auto-pr.yml)

## 実現すること

`auto-pr.yml`が`GITHUB_TOKEN`（`github-actions[bot]`）でPRを自動作成すると、そのPRの`pull_request`イベントで実行される`Lint`ワークフローがGitHub側で承認待ち（`action_required`）状態になり、毎回手動での「Re-run jobs」操作が必要になっていた。過去のPR実績（`run_attempt`）を確認したところ、ユーザー自身が直接push・PR作成した回はattempt 1で自動成功していたのに対し、`auto-pr.yml`がbotとしてPRを作成した回は必ずattempt 2（手動再実行後）まで承認待ちだった。

4リポジトリ共通の`.github/workflows/lint.yml`のトリガーを、作業ブランチへの`push`時点（実際のユーザー操作によるイベント）に変更し、`auto-pr.yml`と同じ`push`イベントで実行させることで、botがPRを自動作成する前にチェックが完了し、承認待ちにならないようにする。`develop`→`main`のリリースPR（人間が直接作成）向けの検証は`pull_request: branches: [main]`として残す。

## 受け入れ条件

- [ ] root/frontend/backend/infra 4リポジトリの`.github/workflows/lint.yml`のトリガーを`push`（`main`・`develop`を除く）＋`pull_request`（`main`向けのみ）に変更している
- [ ] 各リポジトリで実際に作業ブランチをpushし、`auto-pr.yml`によるPR自動作成後にLintチェックが`action_required`にならず自動的にsuccessになることを確認している
- [ ] 変更を各リポジトリの`develop`へマージしている
