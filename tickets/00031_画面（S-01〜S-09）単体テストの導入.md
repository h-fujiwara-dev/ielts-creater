## 実現すること

`ielts-creater-frontend`にはテスト基盤が存在しない（Jest/Vitest等未導入、テストスクリプト・テストファイルともにゼロ、CIでのJS/TS lintも未実行）。S-01〜S-09の全画面実装（#00010, #00018, #00019, #00020, #00021, #00022, #00023, #00024）が完了した現時点で、Vitest + React Testing Libraryによる単体テスト基盤を新規導入し、9画面まとめて1スコープでテストを実装する。

- devDependencies（`vitest`, `@vitejs/plugin-react`, `vite-tsconfig-paths`, `jsdom`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`）を追加し、`vitest.config.ts`・`vitest.setup.ts`を新規作成する
  - `vite-tsconfig-paths`で`tsconfig.json`の`@/*`パスエイリアスをそのまま解決する
  - jsdomに存在しない`matchMedia`/`IntersectionObserver`/`ResizeObserver`をsetupファイルでモックする（`useInView`・`usePrefersReducedMotion`・rechartsの`ResponsiveContainer`が依存するため）
  - `globals: true`は使わず、各テストファイルで`vitest`から明示importする（`tsconfig.json`の`types`変更を避け影響範囲を最小化するため）
- `package.json`に`test`（`vitest run`）・`test:watch`（`vitest`）スクリプトを追加する
- テストファイルは実装ファイルへのco-locate配置（`*.test.tsx`/`*.test.ts`）とする
- 画面コンポーネント（レンダリング・操作）のテストを実装する
  - S-01 Top（`components/sections/*`の代表コンポーネントの疎通確認。単一screenコンポーネントが無いため全網羅はしない）
  - S-02 ログイン/サインアップ（`components/auth/login-signup-flow.tsx`ほか、zodバリデーションエラー表示・react-hook-form連携・ステップ遷移・devユーザー判定による成功/失敗分岐）
  - S-03 問題生成（`components/question-generation/question-generation-screen.tsx`、form→generating→failedの3状態遷移、ポーリングとの整合、searchParamsからのprefill）
  - S-04 回答（`components/answer/answer-screen.tsx`、800msデバウンスautosaveの状態表示、提出フロー）
  - S-05 結果（`components/result/result-screen.tsx`、複数API並行取得の完了待ち）
  - S-06 履歴一覧（`components/history/history-screen.tsx`、タブフィルタ・ページネーション・空状態）
  - S-07 ダッシュボード（`components/dashboard/dashboard-screen.tsx`、フィルタ変更時の再フェッチ）
  - S-08/S-09 プライバシーポリシー・利用規約（`components/legal/legal-page-layout.tsx`ほか、メタ情報・相互リンクの存在）
- ロジック層（`src/lib/`）のテストを実装する（優先度高: `auth/schemas.ts`, `question-sets/schemas.ts`, `auth/dev-user.ts`。優先度中: `utils.ts`, `attempts/storage.ts`）
- CI（GitHub Actions）に新規`.github/workflows/test.yml`を追加し、`npm run lint`（ESLint。現状CI未実行だったギャップの解消を含む）と`npm test`（Vitest）を実行する。既存`lint.yml`（markdownlint専用）はそのまま維持する
- 対象外: E2Eテスト、MSW導入、Cognito実接続テスト、既存UIコードの大規模リファクタリング、`tsc --noEmit`のCI組み込みや`npm run build`のCI実行（将来の別チケット）
