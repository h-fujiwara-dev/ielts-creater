## 実現すること

チケット#00028（受験・回答・採点API）で対象外とした問題生成API（questionset系）4エンドポイントを実装する。AI（OpenAI）・音声合成（Amazon Polly）連携は将来差し替え可能なinterfaceの背後にstub実装を置く方針とし、本チケットでは実際の外部API呼び出しは行わない。

## 受け入れ条件

- [x] JPAエンティティ `Passage` / `ListeningScript` / `AudioSegment` とRepositoryを新規作成する（ER図・テーブル定義.md 3.3〜3.5準拠。`QuestionSet`等は#00028で作成済みのため変更不要）
- [x] `POST /api/v1/question-sets` を実装する（202 Accepted、`{id, status, topic}`。topic未入力時はプリセット8件からサーバー側ランダム選択、100文字超過は400）
- [x] ユーザーごとの1日2回生成回数上限を実装する（超過時 `RateLimitExceededException` → 429、`QuestionSetRepository`への日次カウントクエリ追加）
- [x] 生成処理は`ExecutorService`（Virtual Thread Executor、`common/config`に追加）へ委譲し、リクエストスレッドをブロックしない非同期実行とする
- [x] `generation`パッケージに`ReadingQuestionGenerator`/`ListeningQuestionGenerator` interfaceと、決定的なサンプル問題を生成する`StubReadingQuestionGenerator`/`StubListeningQuestionGenerator`を実装する（TFNG/MCQ/FILL_BLANK/MATCHING_HEADINGSの4形式をReadingで、FORM_COMPLETION/NOTE_COMPLETIONをListeningで生成し、`correct_answer_key`のJSON形状は#00028の採点実装・dev seedと整合させる）
- [x] ルールベース検証（`correctHeadingLabel`が`headingOptions`に存在するか、`maxWords`超過がないか等）を実装し、違反時は1回リトライ、それでも失敗なら`status=FAILED`・`generationError`記録とする
- [x] `listening`パッケージに`StorageService` interfaceと`LocalDiskStorageService`（Phase1用）、`ListeningAudioSynthesizer` interfaceとstub実装を追加し、Listening生成時に台本の発話ごとにダミー音声を生成・ローカル保存する
- [x] `GET /api/v1/question-sets/{id}` を実装する（正解を含まないpassage/questionGroups、生成中は`status=GENERATING`を返す。他ユーザー/存在しないIDは404）
- [x] `GET /api/v1/question-sets/{id}/audio-segments` を実装する（Listening用、ローカル保存した音声を取得可能なURLで返す。Phase1はローカルファイル配信、Phase3でS3署名付きURLに差し替え）
- [x] Unit Test（Mockito）でstub生成器・ルール検証・レート制限分岐・トピックランダム選択を検証する
- [x] 結合テスト（Testcontainers, `@Tag("integration")`）でReading/Listening双方の生成〜ポーリング完了〜詳細取得、Listeningの音声セグメント取得、レート制限429、バリデーション400を検証する
- [x] `./gradlew spotlessCheck test integrationTest` がグリーンであることを確認する
