## 実現すること

チケット#00027で構築したスキャフォールディング（`CurrentUserProvider`によるPhase1固定devユーザー解決、`GlobalExceptionHandler`等）の上に、受験・回答・採点API（attempt系6エンドポイント）を実装する。問題生成API（questionset系）は別チケットのため、採点に必要な最小限の読み取り専用エンティティのみをquestionsetパッケージに用意する。

## 受け入れ条件

- [ ] JPAエンティティ `Attempt` / `AttemptAnswer`、および採点に必要な最小限の読み取り専用エンティティ `QuestionSet` / `QuestionGroup` / `Question` / `AnswerOption` / `AcceptableAnswer` とそれぞれのRepositoryを作成する（ER図・テーブル定義.md 3.2, 3.6〜3.11準拠）
- [ ] `POST /api/v1/attempts` を実装する（受験開始、201、`{id, status}`）
- [ ] `PATCH /api/v1/attempts/{id}/answers` を実装する（回答の部分保存、204 No Content）
- [ ] `GET /api/v1/attempts/{id}/answers` を実装する（保存済み回答の復元。採点情報は含めない。他ユーザー/存在しないIDは404）
- [ ] `POST /api/v1/attempts/{id}/submit` を実装する。`AnswerGrader`(interface) + `GraderFactory` + `TfngGrader`/`McqGrader`/`FillBlankGrader`（FORM_COMPLETION/NOTE_COMPLETION兼用）/`MatchingHeadingsGrader`をStrategyパターンで実装し、`AnswerNormalizer`（trim・空白圧縮・小文字化・末尾句読点除去）で穴埋め系を正規化して判定する。`attempt_answer.is_correct`/`correct_answer_snapshot`と`attempt.raw_score`/`max_score`を更新する
- [ ] `GET /api/v1/attempts/{id}` を実装する（採点済み結果の取得。レスポンス形状はsubmitと同一、`correct_answer_snapshot`から復元）
- [ ] `GET /api/v1/attempts` を実装する（受験履歴一覧。`status=SUBMITTED`のみ対象、`section`/`page`/`size`クエリパラメータ、`submitted_at DESC`固定ソート、既存インデックス`idx_attempt_user_created`を利用）
- [ ] 他ユーザーのAttemptや存在しないIDを指定した場合は404（#00027で実装済みの`ResourceNotFoundException`/`GlobalExceptionHandler`を利用）を返す
- [ ] 手動確認用に、Flywayのローカル専用シード（`db/dev-migration`）へサンプルquestion_set一式（主要出題形式ぶんのquestion_group/question/answer_option/acceptable_answer）を追加する
- [ ] 結合テスト（Testcontainers, `@Tag("integration")`）を、dev seedとは独立したテスト専用フィクスチャで実装する。受験開始→回答保存→提出→採点結果取得→履歴一覧の一連のフローと、4出題形式それぞれの採点結果を検証する
- [ ] Unit Test（Mockito）で`AnswerGrader`各実装と`AttemptSubmissionService`の主要分岐を検証する
- [ ] `./gradlew spotlessCheck test` がグリーンであることを確認する
